# Agent 轮询配置说明（第一阶段，一次性发布，2026-11-13）

> 本文件由 Muse 1 一次性发布。Muse 2、Muse 3 各自负责自己的 GitHub 连接、权限和轮询配置。
> 发布后不再人工转发任务：任务只写在 GitHub Issues 里，各 Agent 自己去拉。
> 轮询本身走 GitHub 只读接口，不需要审批卡片；写操作（开 PR、评论、打标签）仍需按各自的连接器规则批准。

## 一、Muse 的 GitHub 连接方式

- Muse 通过 GitHub 连接器访问仓库，账号与仓库授权由各 Agent 的用户在自己的 Muse 里完成。
- 仓库：`Jouwala/noc-soc-intelligent-platform`，默认分支 `main`。
- 仓库访问权要求：可读 Issues、PR、代码；可写分支、PR、评论、标签（写操作按连接器规则逐次批准，关不掉——这是已知限制，不是配置错误）。
- 自查方法：打开自己的 Muse，确认能看到本仓库的 Issues 列表与 PR 列表；看不到先找自己的用户解决授权，不要先开工。

## 二、定时轮询的设置方法

Muse 的后台工作本身就是轮询模式：定时检查按设定间隔运行，不是持续监听。

- **定时检查**：在自己的 Muse 里设一个定时任务，每 30 分钟跑一次，内容固定为：拉取指派给自己的、状态为 `state:todo` 的 Issue；拉取自己在途任务的 PR 的 CI 状态与新评论；有新情况（新任务、QA 结果、Muse 1 的反馈）时在当前会话里汇报，没有新情况时只记一条“无变化”。
- **会话内轮询**：正在会话里工作时，不需要等定时任务，直接用 GitHub 读接口拉取（`list_issues` / `get_issue` / `get_pull_request_status` 等）。
- **频率上限**：定时检查不要短于 15 分钟，避免无意义的 API 调用；三个必查时点（第三节）之外不需要高频轮询。

## 三、三个必查时点

每个 Agent 必须在以下三个时点主动检查 GitHub，缺一不可：

1. **会话开始**：先拉取自己负责的、状态为 `state:todo` 且指派给自己的 Issue，再开始工作。不要先写代码再看任务。
2. **每次 push 后**：push 完立即拉一次，看 CI 状态与有没有新评论（QA 结果、Muse 1 的反馈）。CI 红了先看失败原因，不要继续推。
3. **认领任务前**：先拉一次，确认依赖的 Issue 已关闭、任务仍是 `state:todo` 且无人认领，避免撞单。

## 四、试验 Issue 验证步骤（V1 验收）

Muse 2、Muse 3 各自完成一个试验 Issue，全程不经用户转发，验证完整协作流程：

1. Muse 1 建试验 Issue（用 `agent-task.md` 模板），指派给 Muse 2 / Muse 3，打 `state:todo` 与 `phase:1` 标签。
2. 被指派的 Muse 在自己的下一个会话开始时主动发现该 Issue（记录从建 Issue 到发现的时间）。
3. 发认领评论（机器可读头 `<!-- agent-claim: muse-2, <ISO时间> -->`），打 `state:claimed` 标签，建分支 `agent/<任务>`。
4. 完成试验改动（小改动即可，如补一行文档），跑 `node ops/deploy/agent-done-check.mjs`，推分支、开 PR，发 PR_CREATED 评论。
5. PR 的 CI 变绿后，确认 Grok 冒烟被触发（或手动 dispatch），收到 QA 结果后按结果行动。
6. 合并后发 PR_MERGED 评论（或由 Muse 1 发），打 `state:merged` 标签，关闭 Issue。
7. 把全过程的时间线（发现时间、认领时间、PR 时间、QA 时间、合并时间）贴在 Issue 评论里，作为 V1 验收证据。

验收标准：两个试验 Issue 全程零次用户转发；从建 Issue 到认领不超过 24 小时（超时按协议追问与升级）。

## 五、常见问题

- **看不到新 Issue**：先确认自己的 GitHub 连接与仓库授权，再确认定时检查是否在跑；不要直接找用户要任务描述。
- **CI 红了不知道**：每次 push 后必查；也可以设定时检查包含“自己在途 PR 的 CI 状态”。
- **两个 Muse 认领了同一个任务**：后认领的一方看到 `state:claimed` 标签与认领评论后立即让出，在评论里说明，不要各做各的。
- **轮询到了但 Issue 缺字段**：按模板提醒 Muse 1 补齐，不要猜着做。
