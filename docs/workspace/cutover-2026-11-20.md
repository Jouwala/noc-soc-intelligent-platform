## 五、风险与未决

1. **门户归属未定**：9267 现在跑的是 `D:\01_RPA\liberia-noc_soc-数据看板统一门户`，不是 `D:\01_olbr_portal` 也不是 02。
   切 02 等于把门户也换实现；`Portal_EnsureRunning` 的任务动作仍指向 `D:\01_RPA`（任务改不动，权限不够，靠 bat 转发）。
   **切前必须明确：门户这次跟不跟。** 不跟就保留 `D:\01_RPA` 的服务，只切 my_app 后端/前端——那样回退面更小。
2. **同一个库被两套代码写**：PG 沿用系统 5432 后，切换窗口内 01 与 02 都可能写库。回退后 01 看到的是 02 写过的数据，**schema 兼容性必须先在 11-19 演练里验证**。
3. **02 的隔离形态别丢**：回退脚本会把 02 的 `.env` 改回 8080/8443/7039/7091/9277/55432 并重生成它的 nginx.conf，这样它继续当隔离副本；否则下次有人在 02 上跑 `start_all.ps1` 会直接抢生产端口。
4. **系统 PG 没有纳入 02 的 start/stop 托管**：02 的 `stop_all.ps1` 只停自己的 `runtime\pgdata`。生产 PG 的拉起仍靠 01 的 `start_ensure.bat`（它会 `pg_ctl start -D "C:\Program Files\PostgreSQL\16\data"`）。这条链路在切换后由谁负责，需要在 11-19 定下来。
