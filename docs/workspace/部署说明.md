### 起停

```bat
cd /d D:\02_olbr_portal
start.bat                   REM → ops\deploy\portal-ctl.ps1 -Action start
stop.bat                    REM → ops\deploy\portal-ctl.ps1 -Action stop
ops\shortcuts\0-status.bat  REM 只读：端口归属 / 健康 / 计划任务
```

`portal-ctl.ps1 -Action start` 的做法是 `schtasks /run` 三个自愈任务
（`MyApp_EnsureRunning` / `Portal_EnsureRunning` / `Nginx_EnsureRunning`），与 5 分钟周期
走同一条代码路径，不是另起一套启动脚本。

入口：

- <https://localhost/>（自签证书，提示不信任属预期）
- <http://192.168.100.20/uniplam/>（门户）
- <http://192.168.100.20/myapp/>（my_app）
- FineBI 在 **.19**：<http://192.168.100.19/webroot/decision>（不经过本机 nginx）

### nginx

```powershell
cd D:\02_olbr_portal\nginx-1.28.0
.\nginx.exe -t          # 改配置后先验证
.\nginx.exe -s reload   # 平滑重载
```

必须先在 nginx 自己的目录里执行 —— 它从**自己的** `logs\nginx.pid` 读 master pid。
运行中的 nginx 占着 `logs\access.log`，`-t` 可能报 access denied，属已知现象
（见 `ops/shortcuts/5-nginx-check.bat` 注释）。

## 二、改完一个改动怎么验证

1. **重建前端**：`apps\my_app\frontend` → `npm run build`（产物必须落 `apps\_fe_dist`）；
   `apps\portal` → `npm run build`。
2. **重启后端**（由人显式执行，避开值班高峰）：`portal-ctl.ps1 -Action restart`。
3. **读 live OpenAPI 对照源码**：`http://127.0.0.1:7038/openapi.json`。前端已含新参数、
   live 后端没有 → `SPLIT-BRAIN`，功能会静默坏掉而不是报错。

冒烟不在生产树上跑：用 `ops\deploy\provision-smoke-runner.ps1 -Apply` 生成项目内 `.smoke\`
副本（`ISOLATED_COPY.flag`），在其中跑 `ops\smoke\smoke.ps1`；流程见 `ops\deploy\README.md`。

## 三、隔离副本（打包机 / 冒烟 runner）

隔离副本的启停走 `ops\deploy\start_all.ps1` / `stop_all.ps1`，**生产树禁止用**：
它们会改 `apps\my_app\backend\.env`、起 55432 的第二套 PG、往 8080/8443 起第二套服务。
`start_all.ps1` 见到 `PRODUCTION.flag` 会直接 throw。

| 端口 | 服务 |
| --- | --- |
| 8080 / 8443 | nginx HTTP / HTTPS（自签证书） |
| 7091 | my_app 前端 vite preview |
| 7039 | my_app 后端 FastAPI |
| 9277 | 统一门户 Express |
| 9278 | WhatsApp 分析服务（`START_WA_ANALYSIS=1` 才起） |
| 9279 | 问答助手（首次提问时按需拉起） |
| 55432 | 便携 PostgreSQL |

入口 `https://localhost:8443/`（导航页）、`/myapp/`、`/uniplam/`、`/v3/olbrportal/`。

安全边界（不要突破）：

- `MY_APP_DISABLE_SCHEDULER=1` 由 `start_all.ps1` **强制**设置：否则采集任务会连生产上游，
  并可能重复投递 WhatsApp / 邮件告警。
- 副本不设 `MY_APP_TASK_QUEUE`，不起 `backend_watchdog` / worker 组 / 计划任务。
- 便携 PG 用 `trust` 认证且只绑回环；`DATABASE_URL` 里没有口令。
- `START_WA_BOT` 默认 0；改成 1 会接管 WhatsApp 会话，**必须先在目标机重新扫码**。

## 四、打包交付（ZIP）

运行时与应用分成两个 ZIP，由 `ops\deploy\build-zip.mjs` 与 `runtime-manifest.json` 驱动：

```bash
# 仅源码模式（验证组装 / 断言 / 凭据扫描，不装依赖）
node ops/deploy/build-zip.mjs --mode source --platform win-x64

# 完整模式（须先 npm ci × 4、npm run build × 2、pip download wheels）
node ops/deploy/build-zip.mjs --mode full --platform win-x64 --version v1.2.3

# 干跑
node ops/deploy/build-zip.mjs --mode source --dry-run
```

产物落 `TMP/zip-dist/`（已忽略）。构建脚本会断言不打包 `pgdata`、`.env`、`*.key`、
会话/凭据、数据库、日志、手工快照。运行时 ZIP 由 `runtime-build.yml` 按清单下载并校验
SHA256；清单里 `url`/`sha256` 为空的条目会直接失败。

安装 / 升级流程仍在推进（Phase 1），现状与缺口见
`docs\workspace\zip-build-release.md`、`docs\workspace\zip-delivery-phase0-review.md`。

> 旧做法（`scripts\build_olbr_portable.ps1 -Stage all` 从 `D:\01_RPA` 打包）**已不在本仓库**，
> 不要照着旧文档跑；新机器补齐运行时按上面的 ZIP / 清单来。

## 五、迁移已有部署（换目录 / 换机）

**`apps/my_app/db/app.db` 里的三张「本地权威表」必须单独搬一次**，否则会出现
「凭据全空 + 任务启停全丢」：

| 表 | 内容 | 写入方 | 丢了会怎样 |
| --- | --- | --- | --- |
| `credentials` | 设置页的账号/口令 | `backend/services/credential/credential_store.py` | 所有任务报「拒绝以空密码登录」 |
| `task_schedule_config` | 任务启停 / cron | `backend/services/task/task_runner.py` | 任务管理页禁用全丢，手动停掉的任务重新开跑 |
| `email_recipients` | 邮件收件人名单 | `backend/services/email/email_recipient_store.py` | 邮件任务没有收件人 |

**为什么它们不会自动跟过来**：这三张表由应用**固定写 SQLite**，PG 里那份只是镜像；
`backend/scripts/sync_pg_to_sqlite.py` 为避免把本地数据 DROP 掉，把它们列进 `SKIP_TABLES`；
「从 PG 重建 app.db」的部署路径**天生带不出它们**，且不会有任何一步报错 ——
2026-11-11 的迁移事故（16 个任务同时报空密码）就是这么来的。

迁移步骤（在能同时看到旧/新两份 `app.db` 的机器上执行一次）：

```powershell
# 1) 先核对：目标为空而源非空时，退出码 2 并列出缺哪张表
python ops\deploy\local_authority_tools.py check `
  --source <旧部署>\apps\my_app\db\app.db `
  --target <新部署>\apps\my_app\db\app.db

# 2) 正式迁移（先把目标表现状备份到新部署的 TMP\，事务内替换，逐行哈希校验）
python ops\deploy\local_authority_tools.py migrate `
  --source <旧部署>\apps\my_app\db\app.db `
  --target <新部署>\apps\my_app\db\app.db

# 3) 复跑 check，必须退出码 0
```

> `TMP\_bak_local_authority_*.json` 含明文口令，只留在本机、不入库、不随包分发；
> 迁移完成后可自行删除。
